## Общие принципы реализации

Все решения строятся по единому подходу.
**Отделение логики от ввода-вывода.** Каждая задача содержит статический метод, принимающий массив и возвращающий результат. Этот метод покрывается тестами JUnit 5. Класс также содержит `main`, который только читает данные из `System.in`, вызывает основной метод и выводит результат. Это позволяет тестировать алгоритм без привязки к консоли.

**Валидация ввода.** В `main` проверяется корректность данных: что введено целое число, что размер массива попадает в допустимые границы, что введено достаточно элементов. При ошибке выводится сообщение, частичный ответ не печатается.

**Константы.** Границы допустимых размеров вынесены в `static final` (`LOWER_BOUND`, `UPPER_BOUND`). Где в задаче есть сигнальное значение (например, `-1` для «не найдено»), оно тоже вынесено в константу (`NOT_FOUND`). Модули и предельные значения (например, `MOD = 10^9 + 7`, `MAX_RANGE = 10^6`) также оформлены как константы.

**Контроль переполнения и типы данных.** Выбор типа зависит от того, какой размах значений может возникнуть:
- Если сумма или произведение могут выйти за пределы `int` (задача 11 — сумма массива, задача 20 — размах значений, задача 25 — сумма элементов), вычисления ведутся в `long`.
- Если и `long` недостаточно (задача 27 — сумма квадратов при n = 10^5 и элементах около `Integer.MAX_VALUE`, задача 31 — скалярное произведение, задача 32 — сумма произведений пар), используется `BigInteger`.
- Если результат по условию дробный (задача 28 — медиана при чётном n, задача 30 — дисперсия), используется `double`.

**Ввод-вывод.** Используется `Scanner`: для n ≤ 10^5 его производительности достаточно, а код читается проще, чем с `BufferedReader`. Сканер закрывается через try-with-resources.

## 1. Задача 1. Максимум и минимум

**Условие.** Вход: массив из n целых чисел. Выход: минимальный и максимальный элементы. Ограничения: 1 < n < 10^5.

### Идея решения

Один проход по массиву. В качестве начальных значений берутся первый элемент (а не `Integer.MAX_VALUE`/`MIN_VALUE`) — это корректно работает на массиве из одинаковых чисел и избавляет от лишних проверок.

На каждой итерации текущий элемент сравнивается с минимумом и максимумом; при необходимости они обновляются.

Сортировка не подходит: она даёт O(n log n) вместо O(n). Два отдельных прохода — та же O(n), но с лишними итерациями.

### Асимптотика

- Время: **O(n)**.
- Доп. память: **O(1)** — две переменные.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `4` / `-7 -15 -2 -9` | `-15 -2` | только отрицательные числа |
| `2` / `8 3` | `3 8` | минимальная допустимая длина |
| `3` / `0 2147483647 -2147483648` | `-2147483648 2147483647` | крайние значения `int` |
| `4` / `4 4 4 4` | `4 4` | все элементы равны |

### Тесты

`MinMaxSearchTest` — 11 тестов: обычный и крайние случаи, все равны, только отрицательные, границы длины, `null`.

## 9. Задача 9. Проверка отсортированности

**Условие.** Вход: массив из n целых чисел. Выход: `YES`, если массив неубывающий; `NO` иначе.

### Идея решения

Один проход: сравниваем `a[i]` с `a[i-1]`. При первом нарушении (`a[i] < a[i-1]`) возвращаем `false` — ранний выход.

Неравенство строгое, а не `<=`: «неубывающий» допускает равные соседи (`1 2 2 3` — корректно).

### Асимптотика

- Время: **O(n)** в худшем, **O(1)** в лучшем.
- Доп. память: **O(1)**.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `5` / `1 2 2 3 5` | `YES` | равные соседи допустимы |
| `5` / `1 3 2 4 5` | `NO` | нарушение в середине |
| `5` / `5 4 3 2 1` | `NO` | строго убывающий |
| `3` / `0 0 0` | `YES` | все равны |
| `1` / `7` | `YES` | один элемент |

### Тесты

`SortedCheckTest` — 11 тестов, включая нарушение только в последнем элементе.

## 10. Задача 10. Индекс последнего кратного k

**Условие.** Вход: массив из n целых чисел и число k (k ≠ 0). Выход: индекс последнего элемента, кратного k, или -1.

Проход с конца массива: первый найденный кратный — и есть последний по индексу. Если последний элемент кратен k, ответ находится за O(1), тогда как проход с начала потребовал бы полного обхода.

`k = 0` отсекается на входе — деление на ноль недопустимо.

### Асимптотика

| `6` / `5 2 9 1 6 7` / k=10 | `-1` | кратных нет |
| `3` / `10 20 30` / k=10 | `2` | все кратны |

## 11. Задача 11. Ближайший к среднему

**Условие.** Вход: массив из n целых чисел. Выход: элемент, ближайший к среднему арифметическому. При равенстве — первый по индексу. Среднее может быть дробным.

### Идея решения

Минимизируем `|a[i] - sum/n|`, что эквивалентно минимизации `|a[i] · n - sum|`. Вычисления в `long`: при `a[i]` около 2^31 и n до 10^5 произведение достигает 2·10^14 — это близко к пределу точности `double`, поэтому `double` дал бы ошибки. `long` считает точно.

Строгое `<` при обновлении минимума обеспечивает выбор первого по индексу при равенстве.

### Асимптотика

- Время: **O(n)** — два прохода.
- Доп. память: **O(1)**.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `6` / `5 2 9 1 7 6` | `5` | среднее 5.0, ближайшие 5 и 7 — первый |
| `3` / `1 2 3` | `2` | среднее целое |
| `2` / `10 20` | `10` | равные расстояния — первый |
| `2` / `2 3` | `2` | среднее 2.5 — нижний сосед |

### Тесты

`ClosestToMeanTest` — 10 тестов, включая переполнение `int` при суммировании.

## 12. Задача 12. Пара с заданной суммой

**Условие.** Вход: массив из n целых чисел и число s. Выход: индексы i < j, для которых `a[i] + a[j] = s`. При нескольких парах — с наименьшим i, при равенстве — с наименьшим j. Если пары нет — `-1 -1`.

### Идея решения

Двойной цикл — O(n²), при n = 10^5 не проходит. Используется `HashMap<значение, индекс>` и проход с конца.

На каждом шаге для `a[i]` проверяется, есть ли `s - a[i]` правее. Каждая новая найденная пара имеет меньший `i`, поэтому после цикла остаётся пара с наименьшим `i`. Перезапись в таблице сохраняет минимальный `j > i`.

Элемент кладётся в таблицу после проверки, чтобы не образовать пару с самим собой.

### Асимптотика

- Время: **O(n)** в среднем, **O(n²)** при катастрофических коллизиях.
- Доп. память: **O(n)**.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `5` / `1 2 3 4 5` / s=5 | `0 3` | пары (0,3) и (1,2): меньший i |
| `3` / `3 1 2` / s=6 | `-1 -1` | 3+3=6, но второй тройки нет |
| `3` / `3 5 3` / s=6 | `0 2` | одинаковые значения на разных индексах |
| `3` / `-5 10 5` / s=5 | `0 1` | отрицательные значения |
| `4` / `2 3 2 3` / s=5 | `0 1` | наименьший i, для него наименьший j |

### Тесты

`PairWithSumTest` — 12 тестов: отсутствие пары, одинаковые значения, «элемент сам с собой», отрицательные числа.

## 16. Задача 16. Сортировка по модулю

**Условие.** Вход: массив из n целых чисел. Выход: отсортированный по неубыванию модуля. При равных модулях первым идёт отрицательный.

### Идея решения

Сортировка с кастомным компаратором: сначала по `|a|`, при равенстве — отрицательный раньше.

Сравнение через `long`: `Math.abs(Integer.MIN_VALUE)` остаётся отрицательным (`-2147483648`), так как в `int` нет `2147483648`. Приведение к `long` даёт `2147483648L` — корректно.

Так как `Arrays.sort` не принимает компаратор для `int[]`, массив преобразуется в `Integer[]` и обратно.

### Асимптотика

- Время: **O(n log n)**.
- Доп. память: **O(n)**.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `5` / `3 -1 5 -2 4` | `-1 -2 3 4 5` | порядок по модулю |
| `4` / `5 -3 3 -5` | `-3 3 -5 5` | равные модули |
| `3` / `-2147483648 2147483647 -1` | `-1 2147483647 -2147483648` | `MIN_VALUE` |

### Тесты

`SortByModulusTest` — 9 тестов, включая `MIN_VALUE`.

## 19. Задача 19. Объединение двух отсортированных массивов

**Условие.** Вход: два массива, отсортированные по неубыванию; размеры n и m. Выход: один отсортированный массив. Требование: O(n + m).

### Идея решения

Два указателя, на каждом шаге берём меньший из текущих и сдвигаем соответствующий указатель. Когда один массив исчерпан — копируем остаток второго.

`Arrays.sort` на объединённом массиве дал бы O((n+m) log(n+m)) — хуже требуемого. `PriorityQueue` тоже работает, но с большей константой.

### Асимптотика

- Время: **O(n + m)**.
- Доп. память: **O(n + m)**.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `3` / `1 3 5`, `3` / `2 4 6` | `1 2 3 4 5 6` | чередование |
| `0`, `3` / `1 2 3` | `1 2 3` | пустой левый |
| `3` / `1 2 3`, `2` / `2 3` | `1 2 2 3 3` | дубликаты |

### Тесты

`MergeSortedTest` — 10 тестов, включая пустые массивы и отказ на неотсортированных входах.

## 20. Задача 20. Сортировка подсчётом

**Условие.** Вход: массив из n целых чисел. Выход: отсортированный по неубыванию. Требование: реализовать сортировку подсчётом.

### Идея решения

Классический counting sort. Ключ — `value - min`, диапазон `max - min + 1` (сдвиг на `min` позволяет работать с отрицательными). Подсчитываем частоты, считаем префиксные суммы (позиции), раскладываем справа налево для стабильности.

Защита от переполнения.При `min = Integer.MIN_VALUE` и `max = Integer.MAX_VALUE` выражение `max - min + 1` равно `2^32`, что не помещается в `int` (переполнение даст отрицательное число). Поэтому размах вычисляется в `long`: `long range = (long) max - min + 1;`. Если `range > MAX_RANGE` (где `MAX_RANGE = 1_000_000L`), бросается `IllegalArgumentException` — иначе `new int[range]` выбросил бы `OutOfMemoryError` или `NegativeArraySizeException`.

### Асимптотика

- Время: **O(n + k)**, где k = max - min + 1.
- Доп. память: **O(n + k)**.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `6` / `5 -3 8 0 -1 2` | `-3 -1 0 2 5 8` | отрицательные и положительные |
| `5` / `2 1 3 1 2` | `1 1 2 2 3` | дубликаты |
| `2` / `-2147483648 2147483647` | ошибка | огромный размах, защита от OOM |

### Тесты

`CountingSortTest` — 9 тестов, включая отказ при огромном размахе.

## 22. Задача 22. Сортировка по частоте

**Условие.** Вход: массив из n целых чисел. Выход: отсортированный по убыванию частоты. При равных частотах — по возрастанию значения.

### Идея решения

`HashMap<значение, частота>` для подсчёта (O(1) в среднем на вставку). Затем ключи сортируются компаратором: по убыванию частоты, при равенстве — по возрастанию значения. Цепочка `comparingInt(...).reversed().thenComparingInt(...)` читается лучше, чем один `compare` с `if`.

Результат заполняется повторением каждого значения `count` раз.

### Асимптотика

- Время: **O(n log n)** в худшем.
- Доп. память: **O(n)**.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `6` / `4 6 5 6 4 6` | `6 6 6 4 4 5` | частоты 3, 2, 1 |
| `3` / `3 1 2` | `1 2 3` | все частоты 1 — по значению |
| `6` / `1 2 3 4 2 3` | `2 2 3 3 1 4` | равные частоты — по значению |

### Тесты

## 25. Задача 25. Сумма элементов

**Условие.** Вход: массив из n целых чисел. Выход: сумма всех элементов.

### Идея решения

Один проход по массиву. Сумма накапливается в переменной типа `long`. Использование `long` обязательно: при n = 10^5 и элементах, близких к `Integer.MAX_VALUE`, сумма достигает 2·10^14, что выходит за пределы `int` (максимум 2.1·10^9). Накопление в `int` привело бы к переполнению и неверному ответу.

### Асимптотика

## 26. Задача 26. Произведение элементов по модулю

**Условие.** Вход: массив из n целых чисел. Выход: произведение всех элементов по модулю 10^9 + 7.

### Идея решения

Один проход по массиву. На каждом шаге текущий результат умножается на очередной элемент, и сразу берётся остаток по модулю `10^9 + 7`. Это предотвращает переполнение: без взятия модуля произведение вышло бы за пределы `long` уже после 10–15 элементов.

Для корректной обработки отрицательных чисел используется формула `(value % MOD + MOD) % MOD`. В Java остаток от деления отрицательного числа отрицателен (например, `-5 % 7 = -5`), а добавление `MOD` переводит его в стандартный диапазон `[0, MOD)`.

### Асимптотика

- Время: **O(n)**.
- Доп. память: **O(1)**.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `4` / `1 2 3 4` | `24` | базовый случай |
| `3` / `5 0 3` | `0` | ноль в массиве |
| `2` / `-2 3` | `1000000001` | отрицательное значение (MOD - 6) |
| `2` / `1000000 1000000` | `999993007` | взятие модуля от 10^12 |

## 27. Задача 27. Сумма квадратов

**Условие.** Вход: массив из n целых чисел. Выход: сумма квадратов всех элементов.

### Идея решения

Для хранения результата используется `BigInteger`. При n = 10^5 и элементах около `Integer.MAX_VALUE` сумма квадратов достигает 4.6·10^23, что не помещается ни в `int`, ни в `long` (максимум `long` — 9.2·10^18). `BigInteger` позволяет корректно обрабатывать такие значения.

Для каждого элемента вычисляется квадрат через `BigInteger.valueOf(value).pow(2)` (это корректно работает и для отрицательных чисел) и добавляется к общей сумме.

### Асимптотика

- Время: **O(n)** (операции с `BigInteger` фиксированной длины — константные).
- Доп. память: **O(1)** (не считая самого `BigInteger` результата).

| `1` / `2147483647` | `4611686014132420609` | квадрат `MAX_VALUE` |
| `3` / `2147483647 2147483647 2147483647` | `13835058042397261827` | переполнение `long` |

## 28. Задача 28. Медиана массива

**Условие.** Вход: массив из n целых чисел. Выход: медиана. При нечётном n — центральный элемент после сортировки. При чётном n — среднее арифметическое двух центральных как `double`.

### Идея решения

Сначала создаётся копия массива, которая сортируется с помощью `Arrays.sort`. Исходный массив не изменяется. Это важно, так как сортировка in-place изменила бы входные данные.

При нечётном n возвращается элемент по индексу `n / 2`. При чётном n берутся два центральных элемента (индексы `n/2 - 1` и `n/2`), и вычисляется их среднее. Перед сложением значения приводятся к `long`, чтобы избежать переполнения `int` при сложении двух `Integer.MAX_VALUE`. Результат делится на `2.0`, чтобы получить дробное число.

### Асимптотика

- Время: **O(n log n)** из-за сортировки.
- Доп. память: **O(n)** для копии массива.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `5` / `5 2 9 1 7` | `5.0` | нечётная длина |
| `4` / `5 2 6 1` | `3.5` | чётная длина, дробный результат |
| `2` / `2147483647 2147483647` | `2.147483647E9` | защита от переполнения `int` |
| `3` / `-5 -1 -9` | `-5.0` | отрицательные числа |

## 29. Задача 29. Мода массива

**Условие.** Вход: массив из n целых чисел. Выход: наиболее часто встречающийся элемент. Если несколько — наименьший по значению. Ограничения: 1 ≤ n ≤ 10^4.

### Идея решения

Для подсчёта частот используется `HashMap<Integer, Integer>`. Это даёт O(1) в среднем на вставку. Сортировка массива дала бы O(n log n), но потребовала бы дополнительного прохода для поиска самой длинной серии, а при равной длине — наименьшего значения.

После подсчёта выполняется проход по всем парам ключ-значение. Выбирается элемент с максимальной частотой; при равенстве частот предпочтение отдаётся меньшему значению.

### Асимптотика

- Время: **O(n)** в среднем (подсчёт + проход по уникальным значениям).
- Доп. память: **O(n)** для хеш-таблицы.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `6` / `1 3 3 2 3 4` | `3` | уникальная мода |
| `5` / `2 4 2 4 1` | `2` | частоты равны (2 и 4) — берём меньший |
| `4` / `7 7 7 7` | `7` | все равны |
| `5` / `5 3 1 4 2` | `1` | все по 1 разу — наименьший |

### Тесты

`ModeTest` — 10 тестов: уникальная мода, равные частоты, все равны, отрицательные, выход за границы n.

## 30. Задача 30. Дисперсия

**Условие.** Вход: массив из n целых чисел. Выход: выборочная дисперсия.

### Идея решения

Используется вычислительно устойчивый вариант: сначала вычисляется среднее, затем сумма квадратов отклонений от него, затем деление на n. Формула `Σa[i]^2/n - mean^2` не применяется: при больших близких значениях она теряет точность из-за вычитания двух больших чисел.

Сумма и отклонения вычисляются в `double` — для n ≤ 10^5 и значений около 2^31 сумма помещается в мантиссу без потери точности.

### Асимптотика

- Время: **O(n)** — два прохода.
- Доп. память: **O(1)**.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `5` / `1 2 3 4 5` | `2.0` | среднее 3, отклонения -2..2 |
| `4` / `5 5 5 5` | `0.0` | все равны |
| `2` / `0 2` | `1.0` | минимальная длина для ненулевой дисперсии |
| `3` / `-1 0 1` | `0.666...` | отрицательные значения |

### Тесты

`VarianceTest` — 9 тестов: все равны, отрицательные, большие значения, один элемент.

## 32. Задача 32. Сумма произведений пар

**Условие.** Вход: массив из n целых чисел. Выход: сумма произведений всех пар `a[i]·a[j]` для `i < j`. Требование: O(n).

### Идея решения

Прямой перебор пар — O(n²). Используется алгебраическое тождество: `Σ_{i<j} a[i]·a[j] = ( (Σa[i])^2 − Σa[i]^2 ) / 2`.

Вычисляются две суммы за один проход: сумма элементов и сумма квадратов. Затем результат получается по формуле. Деление на 2 — точное (числитель всегда чётный, так как это удвоенная сумма произведений).

Результат хранится в `BigInteger`: `(Σa[i])^2` при n = 10^5 и a[i] около `Integer.MAX_VALUE` достигает 4.6·10^23.

### Асимптотика

- Время: **O(n)**.
- Доп. память: **O(1)**.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `3` / `1 2 3` | `11` | 1·2 + 1·3 + 2·3 |
| `2` / `5 5` | `25` | одна пара |
| `4` / `1 -1 2 -2` | `-9` | отрицательные значения |
| `1` / `5` | `0` | одна пара невозможна |

### Тесты

`SumOfPairProductsTest` — 9 тестов: обычный, отрицательные, один элемент, переполнение `long`.
