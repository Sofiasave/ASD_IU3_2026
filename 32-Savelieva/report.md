## Общие принципы реализации

Все решения строятся по единому подходу.
**Отделение логики от ввода-вывода.** Каждая задача содержит статический метод, принимающий массив и возвращающий результат. Этот метод покрывается тестами JUnit 5. Класс также содержит `main`, который только читает данные из `System.in`, вызывает основной метод и выводит результат. Это позволяет тестировать алгоритм без привязки к консоли.

**Валидация ввода.** В `main` проверяется корректность данных: что введено целое число, что размер массива попадает в допустимые границы, что введено достаточно элементов. При ошибке выводится сообщение, частичный ответ не печатается.

**Константы.** Границы допустимых размеров вынесены в `static final` (`LOWER_BOUND`, `UPPER_BOUND`). Где в задаче есть сигнальное значение (например, `-1` для «не найдено»), оно тоже вынесено в константу (`NOT_FOUND`).

**Контроль переполнения.** В задачах, где промежуточные суммы или произведения могут выйти за границы `int` (задача 11 — сумма массива, задача 20 — размах значений), вычисления ведутся в `long`.

**Ввод-вывод.** Используется `Scanner`: для n ≤ 10^5 его производительности достаточно, а код читается проще, чем с `BufferedReader`. Сканер закрывается через try-with-resources.

## 1. Задача 1. Максимум и минимум

**Условие.** Вход: массив из n целых чисел. Выход: минимальный и максимальный элементы. Ограничения: 1 < n < 10^5.

### Идея решения

Один проход по массиву. В качестве начальных значений берутся первый элемент (а не `Integer.MAX_VALUE`/`MIN_VALUE`) — это корректно работает на массиве из одинаковых чисел и избавляет от лишних проверок.

На каждой итерации текущий элемент сравнивается с минимумом и максимумом; при необходимости они обновляются.

Сортировка не подходит: она даёт O(n log n) вместо O(n). Два отдельных прохода — та же O(n), но с лишними итерациями.

### Асимптотика

- Время: **O(n)**.
- Доп. память: **O(1)** — две переменные.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `4` / `-7 -15 -2 -9` | `-15 -2` | только отрицательные числа |
| `2` / `8 3` | `3 8` | минимальная допустимая длина |
| `3` / `0 2147483647 -2147483648` | `-2147483648 2147483647` | крайние значения `int` |
| `4` / `4 4 4 4` | `4 4` | все элементы равны |

### Тесты

`MinMaxSearchTest` — 11 тестов: обычный и крайние случаи, все равны, только отрицательные, границы длины, `null`.

## 8. Задача 8. Фильтрация по знаку

**Условие.** Вход: массив из n целых чисел. Выход: два массива — из положительных и из отрицательных элементов, в исходном порядке. Нули не включаются.

### Идея решения

Один проход, два списка `ArrayList<Integer>`. `ArrayList` выбран потому, что заранее неизвестно, сколько будет положительных и отрицательных: с массивами пришлось бы выделять память с запасом или проходить массив дважды.

Нули игнорируются. Порядок внутри списков сохраняется.

### Асимптотика

- Время: **O(n)**.
- Доп. память: **O(n)**.

### Ручные проверки

| Ввод | Положительные | Отрицательные | Почему важно |
|---|---|---|---|
| `5` / `-1 2 0 -3 4` | `2 4` | `-1 -3` | смешанные знаки, ноль посередине |
| `3` / `1 2 3` | `1 2 3` | — | только положительные |
| `3` / `-1 -2 -3` | — | `-1 -2 -3` | только отрицательные |
| `3` / `0 0 0` | — | — | все нули |

### Тесты

`SignFilterTest` — 10 тестов: смешанный массив, крайние случаи, сохранение порядка, `null`, пустой массив.

## 9. Задача 9. Проверка отсортированности

**Условие.** Вход: массив из n целых чисел. Выход: `YES`, если массив неубывающий; `NO` иначе.

### Идея решения

Один проход: сравниваем `a[i]` с `a[i-1]`. При первом нарушении (`a[i] < a[i-1]`) возвращаем `false` — ранний выход.

Неравенство строгое, а не `<=`: «неубывающий» допускает равные соседи (`1 2 2 3` — корректно).

### Асимптотика

- Время: **O(n)** в худшем, **O(1)** в лучшем.
- Доп. память: **O(1)**.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `5` / `1 2 2 3 5` | `YES` | равные соседи допустимы |
| `5` / `1 3 2 4 5` | `NO` | нарушение в середине |
| `5` / `5 4 3 2 1` | `NO` | строго убывающий |
| `3` / `0 0 0` | `YES` | все равны |
| `1` / `7` | `YES` | один элемент |

### Тесты

`SortedCheckTest` — 11 тестов, включая нарушение только в последнем элементе.

## 10. Задача 10. Индекс последнего кратного k

**Условие.** Вход: массив из n целых чисел и число k (k ≠ 0). Выход: индекс последнего элемента, кратного k, или -1.

### Идея решения

Проход с конца массива: первый найденный кратный — и есть последний по индексу. Если последний элемент кратен k, ответ находится за O(1), тогда как проход с начала потребовал бы полного обхода.

`k = 0` отсекается на входе — деление на ноль недопустимо.

### Асимптотика

- Время: **O(n)** в худшем, **O(1)** в лучшем.
- Доп. память: **O(1)**.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `6` / `5 2 9 1 6 7` / k=3 | `4` | кратные 9 (инд. 2) и 6 (инд. 4), нужен последний |
| `6` / `5 2 9 1 6 7` / k=10 | `-1` | кратных нет |
| `3` / `10 20 30` / k=10 | `2` | все кратны |
| `3` / `-3 -6 -9` / k=3 | `2` | отрицательные кратны положительному |

### Тесты

`LastMultipleTest` — 11 тестов, включая `k = 0`, отрицательный `k`, один элемент.

## 11. Задача 11. Ближайший к среднему

**Условие.** Вход: массив из n целых чисел. Выход: элемент, ближайший к среднему арифметическому. При равенстве — первый по индексу. Среднее может быть дробным.

### Идея решения

Минимизируем `|a[i] - sum/n|`, что эквивалентно минимизации `|a[i] · n - sum|`. Вычисления в `long`: при `a[i]` около 2^31 и n до 10^5 произведение достигает 2·10^14 — это близко к пределу точности `double`, поэтому `double` дал бы ошибки. `long` считает точно.

Строгое `<` при обновлении минимума обеспечивает выбор первого по индексу при равенстве.

### Асимптотика

- Время: **O(n)** — два прохода.
- Доп. память: **O(1)**.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `6` / `5 2 9 1 7 6` | `5` | среднее 5.0, ближайшие 5 и 7 — первый |
| `3` / `1 2 3` | `2` | среднее целое |
| `2` / `10 20` | `10` | равные расстояния — первый |
| `2` / `2 3` | `2` | среднее 2.5 — нижний сосед |

### Тесты

`ClosestToMeanTest` — 10 тестов, включая переполнение `int` при суммировании.

## 12. Задача 12. Пара с заданной суммой

**Условие.** Вход: массив из n целых чисел и число s. Выход: индексы i < j, для которых `a[i] + a[j] = s`. При нескольких парах — с наименьшим i, при равенстве — с наименьшим j. Если пары нет — `-1 -1`.

### Идея решения

Двойной цикл — O(n²), при n = 10^5 не проходит. Используется `HashMap<значение, индекс>` и проход с конца.

На каждом шаге для `a[i]` проверяется, есть ли `s - a[i]` правее. Каждая новая найденная пара имеет меньший `i`, поэтому после цикла остаётся пара с наименьшим `i`. Перезапись в таблице сохраняет минимальный `j > i`.

Элемент кладётся в таблицу после проверки, чтобы не образовать пару с самим собой.

### Асимптотика

- Время: **O(n)** в среднем, **O(n²)** при катастрофических коллизиях.
- Доп. память: **O(n)**.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `5` / `1 2 3 4 5` / s=5 | `0 3` | пары (0,3) и (1,2): меньший i |
| `3` / `3 1 2` / s=6 | `-1 -1` | 3+3=6, но второй тройки нет |
| `3` / `3 5 3` / s=6 | `0 2` | одинаковые значения на разных индексах |
| `3` / `-5 10 5` / s=5 | `0 1` | отрицательные значения |
| `4` / `2 3 2 3` / s=5 | `0 1` | наименьший i, для него наименьший j |

### Тесты

`PairWithSumTest` — 12 тестов: отсутствие пары, одинаковые значения, «элемент сам с собой», отрицательные числа.

## 16. Задача 16. Сортировка по модулю

**Условие.** Вход: массив из n целых чисел. Выход: отсортированный по неубыванию модуля. При равных модулях первым идёт отрицательный.

### Идея решения

Сортировка с кастомным компаратором: сначала по `|a|`, при равенстве — отрицательный раньше.

Сравнение через `long`: `Math.abs(Integer.MIN_VALUE)` остаётся отрицательным (`-2147483648`), так как в `int` нет `2147483648`. Приведение к `long` даёт `2147483648L` — корректно.

Так как `Arrays.sort` не принимает компаратор для `int[]`, массив преобразуется в `Integer[]` и обратно.

### Асимптотика

- Время: **O(n log n)**.
- Доп. память: **O(n)**.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `5` / `3 -1 5 -2 4` | `-1 -2 3 4 5` | порядок по модулю |
| `4` / `5 -3 3 -5` | `-3 3 -5 5` | равные модули |
| `3` / `-2147483648 2147483647 -1` | `-1 2147483647 -2147483648` | `MIN_VALUE` |

### Тесты

`SortByModulusTest` — 9 тестов, включая `MIN_VALUE`.

## 17. Задача 17. Сортировка по сумме цифр

**Условие.** Вход: массив из n неотрицательных целых чисел. Выход: отсортированный по возрастанию суммы цифр. При равных суммах — исходный порядок.

### Идея решения

Сумма цифр для `int` лежит в диапазоне 0..90. Малый фиксированный диапазон позволяет применить сортировку подсчётом — O(n) вместо O(n log n).

Для стабильности используется раскладка справа налево: при проходе слева направо элементы с одинаковым ключом перевернулись бы.

### Асимптотика

- Время: **O(n)**.
- Доп. память: **O(n)**.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `4` / `30 4 10 2` | `10 2 30 4` | суммы цифр 3, 4, 1, 2 |
| `3` / `12 21 3` | `12 21 3` | суммы равны — порядок исходный |
| `4` / `1 0 2 0` | `0 0 1 2` | нули имеют сумму 0 |

### Тесты

`SortByDigitSumTest` — 9 тестов, включая проверку стабильности.

## 18. Задача 18. Сортировка только чётных

**Условие.** Вход: массив из n целых чисел. Выход: массив, в котором чётные отсортированы по неубыванию, а нечётные остались на своих позициях.

### Идея решения

Собираем чётные в отдельный массив, сортируем. Затем идём по копии исходного и подменяем чётные на отсортированные по порядку.

Сортировка всего массива не подходит — нечётные должны сохранить позиции. In-place сортировка только чётных потребовала бы O(n²) на сдвиги.

### Асимптотика

- Время: **O(n log n)**.
- Доп. память: **O(n)**.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `7` / `8 3 6 1 4 7 2` | `2 3 4 1 6 7 8` | чётные на своих позициях отсортированы |
| `4` / `5 3 1 7` | `5 3 1 7` | все нечётные |
| `4` / `-2 1 -4 3` | `-4 1 -2 3` | отрицательные чётные |

### Тесты

`SortEvensOnlyTest` — 10 тестов, включая неизменность исходного массива.

## 19. Задача 19. Объединение двух отсортированных массивов

**Условие.** Вход: два массива, отсортированные по неубыванию; размеры n и m. Выход: один отсортированный массив. Требование: O(n + m).

### Идея решения

Два указателя, на каждом шаге берём меньший из текущих и сдвигаем соответствующий указатель. Когда один массив исчерпан — копируем остаток второго.

`Arrays.sort` на объединённом массиве дал бы O((n+m) log(n+m)) — хуже требуемого. `PriorityQueue` тоже работает, но с большей константой.

### Асимптотика

- Время: **O(n + m)**.
- Доп. память: **O(n + m)**.

### Ручные проверки

| Ввод | Вывод | Почему важно |
|---|---|---|
| `3` / `1 3 5`, `3` / `2 4 6` | `1 2 3 4 5 6` | чередование |
| `0`, `3` / `1 2 3` | `1 2 3` | пустой левый |
| `3` / `1 2 3`, `2` / `2 3` | `1 2 2 3 3` | дубликаты |

### Тесты

`MergeSortedTest` — 10 тестов, включая пустые массивы и отказ на неотсортированных входах.
