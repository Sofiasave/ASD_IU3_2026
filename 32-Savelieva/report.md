## Общие принципы

- **Ввод** — `Scanner` во всех задачах: для n ≤ 10^5 производительности хватает, а читается проще, чем `BufferedReader`. Каждый `main` закрывает сканнер через try-with-resources.
- **Валидация входа** в каждом `main`: нечисловые данные, нарушение границ n, нехватка элементов. При ошибке печатается сообщение, частичный ответ не выводится.
- **Логика отделена от ввода-вывода**: алгоритм — в статическом методе (его тестируем), `main` только читает, вызывает, печатает.
- **Константы вместо магических чисел**: границы n и «сигнальные» значения вынесены в `static final`.
- **Переполнение**: суммы копим в `long`, если `n · 2^31` может не влезть в `int` (задача 11).

## 1. Задача 1. Максимум и минимум

**Условие.** Вход: массив из n целых чисел. Выход: минимальный и максимальный элементы.
Ограничения: 1 < n < 10^5.

### Идея
Один проход, оба экстремума обновляются одновременно. Инициализация первым элементом
избавляет от `Integer.MAX_VALUE`/`MIN_VALUE` и корректно работает на массиве из одинаковых чисел.

Сортировка дала бы O(n log n) вместо O(n); два отдельных прохода — та же O(n), но с лишними итерациями.

### Асимптотика
- Время: **O(n)** — цикл длины n − 1, внутри O(1) сравнений.
- Доп. память: **O(1)** — две переменные и возвращаемый массив фиксированного размера 2.

### Ручные проверки
| Ввод | Вывод | Почему важно |
|---|---|---|
| `4` / `-7 -15 -2 -9` | `-15 -2` | только отрицательные — не путаются границы |
| `2` / `8 3` | `3 8` | минимальная допустимая длина |
| `3` / `0 2147483647 -2147483648` | `-2147483648 2147483647` | крайние значения `int` |
| `4` / `4 4 4 4` | `4 4` | все равны — min и max совпадают |

### Тесты
`MinMaxSearchTest` — 11 тестов: обычный массив, возрастающий, убывающий, все равны,
только отрицательные, крайние `int`, минимальная и максимальная длина, `null`,
длина < 2, длина > 99 999.

## 8. Задача 8. Фильтрация по знаку

**Условие.** Вход: массив из n целых чисел. Выход: два массива — из положительных и из отрицательных
элементов, в исходном порядке. Нули не включаются ни в один.

### Идея
Один проход, два списка `ArrayList<Integer>`. Нули игнорируются. В конце каждый список печатается
в исходном порядке. `ArrayList` выбран, потому что заранее неизвестно, сколько будет положительных
и отрицательных, а массив фиксированной длины пришлось бы обрезать или дополнять.

### Асимптотика
- Время: **O(n)** — один проход.
- Доп. память: **O(n)** — в худшем случае все элементы попадут в списки.

### Ручные проверки
| Ввод | Положительные | Отрицательные | Почему важно |
|---|---|---|---|
| `5` / `-1 2 0 -3 4` | `2 4` | `-1 -3` | смешанные знаки, ноль посередине |
| `3` / `1 2 3` | `1 2 3` | — | только положительные |
| `3` / `-1 -2 -3` | — | `-1 -2 -3` | только отрицательные |
| `3` / `0 0 0` | — | — | все нули — оба списка пусты |

### Тесты
`SignFilterTest` — 10 тестов: смешанный, только положительные, только отрицательные,
все нули, одиночные, сохранение порядка, крайние `int`, `null`, пустой массив.

## 9. Задача 9. Проверка отсортированности

**Условие.** Вход: массив из n целых чисел. Выход: `YES`, если массив неубывающий; `NO` иначе.

### Идея
Сравниваем соседние элементы; первое нарушение (`a[i] < a[i-1]`) — сразу `false`,
дальше проверять нечего. Равенство соседей допускается: это неубывание, не строгая монотонность.

### Асимптотика
- Время: **O(n)** в худшем, **O(1)** в лучшем (нарушение во втором элементе).
- Доп. память: **O(1)**.

### Ручные проверки
| Ввод | Вывод | Почему важно |
|---|---|---|
| `5` / `1 2 2 3 5` | YES | равные соседи — допустимы |
| `5` / `1 3 2 4 5` | NO | нарушение в середине |
| `5` / `5 4 3 2 1` | NO | строго убывающий |
| `3` / `0 0 0` | YES | все равны |
| `1` / `7` | YES | один элемент — тривиально отсортирован |

### Тесты
`SortedCheckTest` — 11 тестов, включая случай «нарушение только в последнем элементе» и пару из двух элементов.

## 10. Задача 10. Индекс последнего кратного k

**Условие.** Вход: массив из n целых чисел и число k (k ≠ 0).
Выход: индекс последнего элемента, кратного k, или −1, если такого нет.

### Идея
Идём с конца массива — первый найденный кратный и есть последний по индексу.
Ранний выход экономит проход. `k = 0` отсекается на входе (деление на ноль недопустимо).

### Асимптотика
- Время: **O(n)** в худшем, **O(1)** в лучшем (последний элемент кратен k).
- Доп. память: **O(1)**.

### Ручные проверки
| Ввод | Вывод | Почему важно |
|---|---|---|
| `6` / `5 2 9 1 6 7` / k=3 | 4 | кратные 9 (инд. 2) и 6 (инд. 4), нужен последний |
| `6` / `5 2 9 1 6 7` / k=10 | -1 | кратных нет |
| `3` / `10 20 30` / k=10 | 2 | все кратны — последний |
| `3` / `-3 -6 -9` / k=3 | 2 | отрицательные кратны положительному |

### Тесты
`LastMultipleTest` — 11 тестов, включая `k = 0`, отрицательный `k`, одиночный элемент.

## 11. Задача 11. Ближайший к среднему

**Условие.** Вход: массив из n целых чисел. Выход: элемент массива, ближайший к среднему арифметическому.
Если несколько — вывести первый по индексу. Ограничение: среднее может быть дробным.

### Идея
Среднее может быть дробным, поэтому сравниваем **не сами расстояния** в `double`, а их
эквивалент в целых: `|a[i] · n − S|`, где `S` — сумма. Обе части — `long`
(`n · 2^31` ≈ 2·10^14 помещается в `long`). Строгое `<` при обновлении минимума
гарантирует, что при равенстве остаётся первый по индексу элемент.

### Асимптотика
- Время: **O(n)** — один проход для суммы, второй — для поиска минимума расстояния.
- Доп. память: **O(1)**.

### Ручные проверки
| Ввод | Вывод | Почему важно |
|---|---|---|
| `6` / `5 2 9 1 7 6` | 5 | среднее 5.0, ближайшие 5 и 7 — первый по индексу |
| `3` / `1 2 3` | 2 | среднее целое, совпадает с элементом |
| `2` / `10 20` | 10 | среднее 15.0, равные расстояния — первый |
| `2` / `2 3` | 2 | среднее 2.5 — берётся нижний сосед |

### Тесты
`ClosestToMeanTest` — 10 тестов, включая случай, где сумма переполнила бы `int` (крайние значения).

## 12. Задача 12. Пара с заданной суммой

**Условие.** Вход: массив из n целых чисел и число s. Выход: индексы i < j, для которых
`a[i] + a[j] = s`. Если пар несколько — пара с наименьшим i, при равенстве — с наименьшим j.
Если пары нет — `-1 -1`.

### Идея
Двойной цикл — O(n²), при n = 10^5 это ~5·10^9 операций. Используем `HashMap<значение, индекс>`
и проход **справа налево**. Для текущего `i` проверяем, есть ли `s − a[i]` правее:
если да, пара `(i, j)` найдена. Каждая новая найденная пара имеет меньший `i`,
поэтому после цикла остаётся пара с наименьшим `i`. Перезапись в таблице
(`put`, не `putIfAbsent`) при обратном проходе сохраняет **минимальный** `j > i` для
каждого значения, так что и `j` минимален. Элемент кладётся в таблицу **после** проверки,
чтобы не образовать пару с самим собой.

### Асимптотика
- Время: **O(n)** в среднем, **O(n²)** в худшем при катастрофических коллизиях HashMap
  (на практике для `int` не достигается).
- Доп. память: **O(n)**.

### Ручные проверки
| Ввод | Вывод | Почему важно |
|---|---|---|
| `5` / `1 2 3 4 5` / s=5 | `0 3` | пары (0,3) и (1,2): приоритет — меньший i |
| `3` / `3 1 2` / s=6 | `-1 -1` | 3+3=6, но второй тройки нет — нельзя составлять пару с собой |
| `3` / `3 5 3` / s=6 | `0 2` | пары из одинаковых значений на разных индексах |
| `3` / `-5 10 5` / s=5 | `0 1` | отрицательные значения |
| `4` / `2 3 2 3` / s=5 | `0 1` | наименьший i = 0, для него наименьший j = 1 |

### Тесты
`PairWithSumTest` — 12 тестов, включая отсутствие пары, пару из одинаковых значений,
случай «элемент сам с собой», отрицательные числа, отрицательную сумму.
